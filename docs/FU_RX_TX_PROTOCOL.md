# ФУ: одновременно приём и передача (RX+TX)

Контракт для согласования между ПО ПК, бриджем и прошивкой МК.
Сторона ПК реализована в ветке `feature/fu-rx-tx`. Поддержка команды в МК
требует отдельной реализации и проверки на оборудовании.

## Коды ФУ

| Код | Режим |
| --- | --- |
| `0x00` | Приём (RX), существующий |
| `0x01` | Передача (TX), существующий |
| `0x02` | Одновременный приём и передача (RX+TX), новый |

Это **FU**, не TU. `sign = 0x01`. Команда `0x02` заменяет режим одним
действием на МК, а не требует двух последовательных команд от ПК.

## Запрос: 8 байт

| Смещение | Поле | Формат |
| --- | --- | --- |
| 0–1 | `address` | Маска адреса ППБ, 16 бит, big-endian |
| 2 | `command` | `0x02` |
| 3 | `sign` | `0x01` (FU) |
| 4 | `fu_period` | Старший байт длительности (`duration >> 8`) |
| 5 | `fu_data[0]` | Старший байт длительности |
| 6 | `fu_data[1]` | Младший байт длительности |
| 7 | `fu_data[2]` | Скважность, % |

Все четыре байта параметров всегда передаются, даже если некоторые равны нулю.
Длительность — `1..27000`, скважность — `1..99`; GUI также сохраняет
существующую проверку длительности нуля.

Пример: ППБ №1, длительность `100`, скважность `30`:

```text
00 01 02 01 00 00 64 1E
```

Пример с ненулевым `fu_period`: адресная маска `0x0002`,
длительность `0x1234` (4660), скважность `45`:

```text
00 02 02 01 12 12 34 2D
```

Повторение старшего байта длительности в `fu_period` и `fu_data[0]`
— существующее соглашение стороны ПК, не новая интерпретация протокола.
Если МК ожидает другую семантику `fu_period`, контракт нужно скорректировать
до прошивки и эксплуатации.

## Ответ бриджа: 4 байта

| Смещение | Значение |
| --- | --- |
| 0–1 | Адресная маска, big-endian |
| 2 | `0x02` — эхо команды |
| 3 | `0x01` — ОК, `0x00` — ошибка |

Примеры: `00 01 02 01` (успех), `00 01 02 00` (ошибка).

## Проверки совместимости

- Старые запросы `0x00` и `0x01` не меняются.
- Новая команда отправляется одним FU-пакетом со всеми байтами параметров.
- Ответ `0x02` принимается, неизвестные номера отклоняются.
- Прошивка МК отвечает за фактическое переключение двух трактов.
- Проверка сборки и программных пакетов не подтверждает аппаратную поддержку.
